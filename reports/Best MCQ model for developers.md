# Pick Gemini Flash for Screenshot Quizzes

**DeepSeek is the cheapest, Gemini gives the best answers, and the best overall pick for your agent is `gemini-3.8-flash` at `medium` thinking.** `deepseek-flash` costs about $1.50 to $6.60 per 1,000 questions by my estimate. `gemini-4-argon` is the pick on all four topics: full stack, solution architecture, GitHub and Git, and scenario questions. It is not the overall pick, because it has the highest list price, that price doubles on 1 December 2026, and it has no pure multiple-choice (MCQ) score yet. Gemini 3.8 Flash has the best image MCQ score in this comparison. It costs about $9 to $20 per 1,000 questions until its own price doubles on 1 January 2027. It also shares its API with Argon, so moving up later means changing one model name. Gemini is the only provider that documents a 0 to 1000 position format, and your click depends on that. So I would change the default in `mcq_agent.py`, which is `grok-4.7` today. No model has been tested on your real job: reading a developer quiz from a screenshot and clicking the answer. So the evidence is strong for prices, medium for answers and weak for clicks. Prices are as of 1 November 2026.

### Full stack: Argon leads, and DeepSeek comes close

No test asks full stack MCQs on these models, so this pick comes from nearby tests. Argon is first or second on SQL, React bug fixing and exact software facts. It also leads on building web apps, with 91.91 on Vibe Code Bench against 87.73 for DeepSeek, 86.17 for Grok 4.7 and 78.65 for Flash ([Vals](https://www.vals.ai/benchmarks/vibe-code)). DeepSeek is the surprise. It beats Argon on written code questions and nearly ties it on total bug fixing, 42.7 to 40.7 out of 105 ([Bug Hunt Bench](https://bughunt.productcompass.pm/data/benchmark.json)). But those tests let a model run tools and try again, and a quiz gives one try. DeepSeek's weak spot is SQL, at 22.8 on strict scoring and 63.8 after a review of its answers ([AIM](https://aimultiple.com/text-to-sql)). **Evidence: medium.** Many independent tests point the same way, but none of them is an MCQ test.

### Solution architecture: concept questions are nearly a tie

I found no score for any current model on an AWS, Azure or Google Cloud exam. The only named results use GPT-3 and GPT-4 era models from 2023 ([Noever and Ciolino](https://arxiv.org/abs/2305.05377)). The closest test is SAKE, with 2,154 four-option architecture questions on older models. Scores sat between 89.31 and 94.23, and the authors call the best models "close to interchangeable". Gemini 3.1 Flash Lite, a cheap model still on sale, scored 93.66 ([SAKE](https://arxiv.org/pdf/2606.29520)). So a higher price buys very little on concept questions. Product detail is different. On Cisco exam questions, Gemini 2.5 Flash Lite scored 74.0 and Gemini 2.5 Pro scored 91.5 ([CyberCertBench](https://arxiv.org/html/2604.20389v1)). Cloud exams mix concepts and product detail, so I pick the model with the strongest hard knowledge. Argon also ranks 2nd on Arena's votes for software and IT prompts, against 23rd for Flash, 84th for Qwen and 100th for Grok 4.7, though votes show preference and not correctness ([Arena](https://arena.ai/leaderboard/text/industry-software-and-it-services)). The best case against Argon is AA-Briefcase, where Grok 4.7 (1638) and DeepSeek (1570) beat it (1484). That test grades long business documents, not one choice ([Artificial Analysis](https://artificialanalysis.ai/evaluations/aa-briefcase)). **Evidence: weak.** The architecture tests used older models, and the tests on current models are not about architecture.

### GitHub and Git: no test exists, so the pick rests on exact facts

I found no test of Git or GitHub MCQs on any of these models, and no study of any AI model on GitHub certification exams. Terminal-Bench 4.0 does not help, because none of its 66 task instructions mentions Git ([Terminal-Bench](https://github.com/harbor-framework/terminal-bench/tree/main/tasks)). So this pick rests on memory for exact facts. On SimpleQA Verified, Argon scored 76, Flash 70 and Grok 4.7 56 ([Epoch](https://epoch.ai/models/gemini-4-argon); [Epoch](https://epoch.ai/models/gemini-3-8-flash); [Epoch](https://epoch.ai/models/grok-4-7)). Argon also leads the software facts row above, with two cautions. That test has no Git or shell category, and it rewards refusing. Argon answered only 52.4% of its questions, and a quiz forces an answer, so part of that lead goes away. Across all subjects, raw accuracy is close: Flash 50.5, Argon 48.3. More thinking will not fix a missing fact, since Flash moves only from 48.3 at `low` to 50.5 at `high` ([AA-Omniscience](https://artificialanalysis.ai/evaluations/omniscience)). Trap formats are a risk for every model. On "select all that apply" questions, the best older model got only 41.77% fully right ([SATA-Bench](https://arxiv.org/html/2506.00643v3)). New GitHub features are another risk, because Flash's knowledge stops at March 2026 ([Google](https://deepmind.google/models/model-cards/gemini-3-8-flash/)). **Evidence: very weak.** Every number here comes from another subject or an older model.

### Scenario questions: thinking matters more than memory

Scenario questions ask a model to work through a situation, so logic tests are the nearest match. LiveBench's reasoning set has 202 short questions with one right answer ([LiveBench](https://livebench.ai/data/20261014/notes.json)). Argon ranked 1st of 55 with 95.1, Flash (89.3) and DeepSeek (89.1) tied, and Grok 4.7 (82.7) and Qwen (80.0) came behind ([LiveBench](https://livebench.ai/data/20261014/table.csv)). It is one run, so gaps under about 5 points mean little. On ARC-AGI-2 puzzles at `medium`, Argon solved 87.1% and Flash 82.9% ([ARC Prize](https://arcprize.org/media/data/evaluations.json)). Thinking must stay on: without it, DeepSeek falls from 80.6 to 69.2 on image MCQs ([Artificial Analysis](https://artificialanalysis.ai/evaluations/mmmu-pro)). Argon also needs at least `medium`, because it fell to 42.1% at `low` on ARC. Git scenarios carry a special risk. In one study of older models, about 92% of errors came from ignoring the state of the working folder, such as switching branches with conflicting changes ([Git-Assistant](https://arxiv.org/html/2607.09224)). **Evidence: medium.** The lead is clear and independent, but these are logic tests, not developer scenarios.

## DeepSeek is cheapest, but thinking sets the bill, not the screenshot

Providers charge per token, which is a small piece of a word. A screenshot is cheap everywhere: about 1,024 tokens on DeepSeek ([DeepSeek](https://api-docs.deepseek.com/guides/vision)), 1,120 on Gemini 3 and 4 by default ([Google](https://ai.google.dev/gemini-api/docs/media-resolution)) and 2,048 on Groq ([Groq](https://console.groq.com/docs/vision)). That is under half a cent per image. xAI publishes no number, so Grok's image cost stays unknown until you read `image_tokens` in a real reply ([xAI](https://docs.x.ai/developers/rest-api-reference/inference/chat-completions.md)).

The real cost is thinking. Thinking tokens are notes a model writes for itself before it answers, and you pay for them at the output price ([Google](https://ai.google.dev/gemini-api/docs/pricing)). Grok 4.7 cannot turn thinking off ([xAI](https://docs.x.ai/developers/model-capabilities/text/reasoning.md)), and neither can Gemini 3 and 4 models ([Google](https://ai.google.dev/gemini-api/docs/thinking)).

Your README says each question uses at least two model calls, so this table counts two calls per question. It is my estimate. It uses about 730 tokens for your prompt and schema, measured from `mcq_agent.py`, and a 300-token JSON reply. The thinking columns are assumptions. Older models used 590 to 1,611 tokens on MCQs at medium settings, so this range is fair for normal questions ([ReasonLab](https://arxiv.org/html/2607.14109v2)). Hard questions can use far more.

The easiest saving in your code is the second call, which only confirms the click and finds Next but repeats all the thinking. **Evidence: strong for list prices, medium for real cost.** The prices are published, but the thinking amounts are assumptions until you measure them.

## Every model reads text well, but pointing separates them

Your agent asks one call to read the screen, pick the answer and give a position. Reading is close. Pointing is not. The table shows the nearest tests, and none of them uses browser screenshots. Roboflow's images are labels, meters and forms, each model ran once, and these columns are scored by rule, not by an AI judge ([Roboflow](https://playground.roboflow.com/evals/ocr)). ParseBench uses PDF pages and is run by LlamaIndex, whose own products lead that board ([ParseBench](https://raw.githubusercontent.com/run-llama/ParseBench/main/leaderboard.csv)).

| Model | Reads plain text, low / high | Reads one exact value, low / high | Finds text in the image, low / high | Links text to its place on a page | Documents 0 to 1000 output |
|---|---|---|---|---|---|
| `gemini-4-argon` | 95.5 / 98.8 | 78.3 / 80.0 | **81.5 / 84.7** | No row | Yes |
| `gemini-3.8-flash` | 91.3 / 94.1 | 73.5 / 70.9 | 26.4 / 58.6 | 67.46 to 70.01 | Yes |
| `gemini-3.5-flash-lite` | 87.5 / 88.6 | 64.3 / 66.1 | 31.9 / 46.4 | 54.85 to 57.81 | Yes |
| `grok-4.7` | 89.5 at low | 54.4 at low | 14.8 at low | No row | No |
| `deepseek-flash` | No row | No row | No row | 21.75 to 28.04 | No |

Plain text reading runs from 87.5 to 98.8, while finding text runs from **14.8 to 84.7**. Argon's lead over Flash here is the cleanest gap in the table, because both use the same Google format. Flash at `low` is poor at this, and `medium` is untested. The test is also strict: the box must overlap the real spot by more than half and the text must match exactly. That is harder than landing a click inside an option row. Grok's weak pointing has a caveat. Roboflow's object detection test, where it scored 40.4, gives every model Gemini's y-first order, which may not suit other models ([Roboflow](https://playground.roboflow.com/evals/object-detection)).

Only Gemini documents position output. It returns `box_2d` as [ymin, xmin, ymax, xmax], scaled to 0 to 1000 and relative to the image, so it stays valid if the image is resized ([Google](https://ai.google.dev/gemini-api/docs/image-understanding)). xAI and DeepSeek document nothing ([xAI](https://docs.x.ai/developers/model-capabilities/images/understanding); [DeepSeek](https://api-docs.deepseek.com/guides/vision)). Your grid itself is fine, by my arithmetic: one unit is 1.92 pixels across and 1.08 down, so a 16-pixel radio button is about 8 by 15 units.

Real web pages have little data. Gemini 3.1 Flash-Lite is the only model here tested on them, with 85% on buttons and links and 78% on radio and checkbox tasks at 1280×720. The older Gemini 3 Flash scored 96% on both, and an older Qwen model scored 68% and 62% ([ComponentBench](https://arxiv.org/pdf/2608.18307)). Those tasks allowed up to 20 steps, so they do not prove one-shot accuracy. I found no test of selected-state reading on any of these models, and none on small interface text, code screenshots or dark themes. Older agents were least reliable when the right state was already set, and they tended to click anyway ([See, Think, Act](https://arxiv.org/html/2509.13615v5)). This matters in your code, because `selected` decides whether to click again. On a checkbox, one wrong read would untick a right answer.

## Flash is the safest first step, and Argon is one name away

This is the closest call in the report. Flash wins because it is proven in the format you need. It ranks 4th of 93 on image MCQs and 5th of 138 on MMLU-Pro ([Vals](https://www.vals.ai/benchmarks/mmmu); [Vals](https://www.vals.ai/benchmarks/mmlu_pro)). Three labs agree on its GPQA Diamond score, at 94.44 to 95.3 ([Artificial Analysis](https://artificialanalysis.ai/evaluations/gpqa-diamond); [Vals](https://www.vals.ai/benchmarks/gpqa); [Epoch](https://epoch.ai/models/gemini-3-8-flash)). An earlier Flash was one of only two models out of 60 to pass all 30 software testing exams ([ISTQB study](https://arxiv.org/html/2603.23142)). Google also recommends 3.8 Flash for its Computer Use tool, though that tool uses a different API from your code ([Google](https://ai.google.dev/gemini-api/docs/computer-use)). Its risks are real. It finds text poorly at `low`, it gave wrong answers on 27.3% of hard fact questions, and its thinking bill can grow. **Evidence: medium for answers, weak for clicks.**

Argon is better on almost every test above that scored it, and it could end up close to Flash in real cost. I still start with Flash for four reasons. Argon has no pure MCQ score. It costs 2.7 to 5.3 times more per token. It has no free tier ([Google](https://ai.google.dev/gemini-api/docs/pricing)). It was also slower at `high`, at 46.49 seconds for a full reply against 31.10 on a text test ([Artificial Analysis](https://artificialanalysis.ai/models/gemini-4-argon/providers); [Artificial Analysis](https://artificialanalysis.ai/models/gemini-3-8-flash/providers)). Starting cheap and moving up on your own results risks little, because the move is one model name. If money is tight, step down to `gemini-3.5-flash-lite`, not DeepSeek. It keeps the same format, scored 83.58 on image MCQs and 85.84 on MMLU-Pro, and gave a full reply in 7.94 seconds ([Vals](https://www.vals.ai/benchmarks/mmmu); [Vals](https://www.vals.ai/benchmarks/mmlu_pro); [Artificial Analysis](https://artificialanalysis.ai/models/gemini-3-5-flash-lite/providers)). Avoid `gemini-3.1-flash-lite` for new work, because Google can shut it down from 7 May 2027 ([Google](https://ai.google.dev/gemini-api/docs/deprecations)).

The other three each fail a need of this agent. **DeepSeek** has no documented position format, the lowest score for placing text on a page, and no JSON schema mode ([DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion.md)). It gave the most wrong answers on hard facts of the image models here, at 38.7% of all questions, a figure worked out from AA's data ([AA-Omniscience](https://artificialanalysis.ai/evaluations/omniscience)). It stores data in China, and nothing shows that its opt-out covers API calls ([DeepSeek](https://cdn.deepseek.com/policies/en-US/deepseek-privacy-policy.html); [DeepSeek](https://cdn.deepseek.com/policies/en-US/deepseek-terms-of-use.html)). That matters because your agent sends the whole screen. **Grok 4.7** is "primarily a text model" in xAI's own words ([xAI](https://media.x.ai/v1/website/card4p7-3a96f40b.pdf)). Your code runs it at its default `high` level, and at top thinking it used the most tokens on LiveBench. xAI also calls Chat Completions, the API your code uses, a legacy endpoint ([xAI](https://docs.x.ai/developers/model-capabilities/legacy/chat-completions.md)). **Groq** has only Preview image models, and Groq says Preview models "should not be used in production environments" ([Groq](https://console.groq.com/docs/models)). Qwen also came last on exact software facts. Your code also sets no thinking level, and Groq's pages disagree on the default, so it may run with thinking off, its weakest mode ([Groq](https://console.groq.com/docs/api-reference); [Groq](https://console.groq.com/docs/reasoning)). Turning thinking up has its own risk. Groq's output cap is 16,384 tokens, and Qwen averaged 24,786 at top thinking on LiveBench ([Groq](https://console.groq.com/docs/model/qwen/qwen3.8-27b); [LiveBench](https://livebench.ai/data/20261014/cost.csv)). No test shows cut-offs on Groq yet.

The laptop has no GPU, so all of these run in the cloud and its power does not limit the choice. To switch, add a `gemini` entry to `PROVIDERS` with base URL `https://generativelanguage.googleapis.com/v1beta/openai/` and `SCHEMA_FORMAT`. Google says this layer is still in beta, and it can reject complex schemas with HTTP 400, so start with `--dry-run` ([Google](https://ai.google.dev/gemini-api/docs/openai); [Google](https://ai.google.dev/gemini-api/docs/structured-output)). Set `reasoning_effort` to `medium` in the code. For Flash, `low` to `medium` lifts AA's index from 22.3 to 30.0, while `high` adds only 0.5 ([Artificial Analysis](https://artificialanalysis.ai/evaluations/terminalbench-4-0)). The only image timing I found for Flash is 12.60 seconds per image at `low` and 79.76 at `high` ([Roboflow](https://playground.roboflow.com/evals/ocr)). Google does not publish its paid rate limits, so watch for rate errors in your test ([Google](https://ai.google.dev/gemini-api/docs/rate-limits)). Use a paid key on real screens. Google keeps paid content out of product improvement, but it keeps logs for up to 55 days ([Google](https://ai.google.dev/gemini-api/terms); [Google](https://ai.google.dev/gemini-api/docs/usage-policies)).

Four small code changes follow from the evidence. Put the text before the image, as Google advises, because your code sends the image first ([Google](https://ai.google.dev/gemini-api/docs/image-understanding)). Test Google's box format and click the center of the box around the whole option, instead of one `x, y` point on a radio dot. Move `selected` above `answers` in the schema, since older agents gained over 30% on toggles when they stated the current state first ([See, Think, Act](https://arxiv.org/abs/2509.13615)). For checkboxes, compare the pixels around the click before and after, so a second click never depends on the model's `selected` alone. Do not add an "are you sure?" step. On older models it flipped answers about 46% of the time and cut accuracy by 17% ([arXiv 2311.08596](https://arxiv.org/abs/2311.08596)).

## Conclusion

The price lists suggest a simple trade between cheap and good, and the evidence does not support it. Thinking sets the bill, so a model with a higher token price can cost less per question. MCQ format also squeezes the gaps: Flash-Lite trails Flash by only 4.38 points on MMLU-Pro, yet by 552 points on AA-Briefcase ([Vals](https://www.vals.ai/benchmarks/mmlu_pro); [Artificial Analysis](https://artificialanalysis.ai/evaluations/aa-briefcase)). The widest gaps are in finding positions, and selected-state reading has no test at all. So my judgment is that the next dollar should go to checking clicks, not to a smarter model. Choosing Gemini as the provider is also safer than choosing one model. Flash-Lite, Flash and Argon share one API and one position format, and their prices are about to move.

The next step is a small test, not more reading. Take about 100 screenshots with answers you have checked yourself, because practice banks can carry wrong keys ([example listing](https://apps.apple.com/us/app/id1624259317)). Cover all four topics, code blocks, dark themes and select-all questions. Run `gemini-3.8-flash`, `gemini-4-argon`, `gemini-3.5-flash-lite` and `deepseek-flash` twice each. Record right answers, click hits, the `selected` field, tokens from `usage` and time. By my estimate this costs under $10 if you run it before 1 December, while Argon is half price. My suggested rules are simple. Move to Argon if Flash misses more than 5 clicks in 100, or if Argon's real cost is under twice Flash's. Move down to Flash-Lite if it stays within 3 right answers of Flash. Check again after 1 January, when Flash doubles.
